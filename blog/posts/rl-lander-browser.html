Landing the Actor-Critic: DQN, A2C & PPO in the Browser

// 1,207 parameters, zero GPUs, and the visualization that makes RLHF click

01 // THE SETUP

After building RL Pong with Q-Learning, DQN, and REINFORCE, the natural next step was the algorithm family that actually runs the modern world: Actor-Critic methods. A2C is how DeepMind's agents learn. PPO is how ChatGPT was aligned via RLHF. And if you read When GANs Meet RL, you already know the punchline — the actor is the generator, the critic is the discriminator. Same adversarial game, different costume.

Lunar Lander was the obvious vehicle. It fits the space theme, has intuitive physics anyone can understand (gravity goes down, thrust goes up), and the 6-action space is rich enough to show real behavioral differences between algorithms. Most importantly, the actor-critic split is visually demonstrable: you can watch the critic’s confidence rise as the lander approaches the pad, and the actor concentrate probability mass onto main-thrust.

The goal: implement DQN (baseline visitors know from Pong), A2C (the core teaching algorithm), and PPO (the modern standard) — all training live in the browser with a real-time actor-critic visualization panel.

02 // THE THREE ALGORITHMS

DQN — The Baseline

DQN is the same Double DQN from Pong, scaled up to 6 actions. One network estimates $Q(s, a)$ for all actions; the agent picks $\arg\max_a Q(s, a)$ (with $\epsilon$-greedy exploration). The target network stabilizes learning:

$$Q(s, a) \leftarrow r + \gamma \, Q_{\text{target}}(s', \arg\max_{a'} Q_{\text{online}}(s', a'))$$

Architecture: MiniNet(8, 64, 6) = 966 parameters. It works, but it only learns values — there’s no explicit policy. This is where actor-critic enters.

A2C — Advantage Actor-Critic

A2C splits the brain in two. The Actor $\pi_\theta(a|s)$ is a policy network that outputs a probability distribution over actions. The Critic $V_\phi(s)$ is a value network that estimates how good the current state is. The key insight: instead of using raw returns as in REINFORCE, we use the advantage:

$$A(s, a) = r + \gamma \, V_\phi(s') - V_\phi(s)$$

This is the TD (temporal difference) advantage — “how much better was this outcome than what the critic expected?” A positive advantage means “do more of this,” negative means “do less.” The actor’s policy gradient becomes:

$$\nabla_\theta J \approx \nabla_\theta \log \pi_\theta(a|s) \cdot A(s, a)$$

And the critic trains via MSE on the TD target:

$$\mathcal{L}_{\text{critic}} = \Big( r + \gamma \, V_\phi(s') - V_\phi(s) \Big)^2$$

Two networks, two loss functions, one elegant loop. Actor: MiniNet(8, 48, 6) = 726 params. Critic: MiniNet(8, 48, 1) = 481 params. Total: 1,207 parameters.

PPO — Proximal Policy Optimization

PPO is A2C with guardrails. The problem with vanilla policy gradients: a single bad update can destroy a good policy. PPO’s fix is the clipped surrogate objective:

$$L^{\text{PPO}} = \mathbb{E} \Big[ \min\!\big( r_t(\theta) \, A_t, \; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \, A_t \big) \Big]$$

where the importance ratio $r_t(\theta) = \pi_\theta(a_t|s_t) / \pi_{\theta_{\text{old}}}(a_t|s_t)$ measures how much the policy has changed. If the ratio drifts too far from 1 (policy changed too much), the clipping kicks in and stops the gradient. This is why PPO is the algorithm of choice for RLHF — it makes large policy changes safely.

PPO also uses Generalized Advantage Estimation (GAE) instead of single-step TD:

$$\hat{A}_t = \sum_{l=0}^{T-t} (\gamma \lambda)^l \, \delta_{t+l}, \quad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

The $\lambda$ parameter (0.95 here) interpolates between high-bias/low-variance (TD, $\lambda=0$) and low-bias/high-variance (Monte Carlo, $\lambda=1$). Same architecture as A2C: 1,207 parameters.

03 // THE PHYSICS

Everything runs in an 800×600 logical coordinate space (same as Pong). The physics are deliberately simple — just enough to make landing non-trivial:

  • Gravity: 0.05 px/frame² downward (gentle moon gravity)
  • Main thrust: 0.12 px/frame² along the lander’s up axis
  • Side thrusters: 0.04 px/frame² for lateral translation
  • Rotation: ±0.04 rad/frame, with angular damping of 0.98
  • Wind gusts: random, max 0.02 px/frame² (enabled at curriculum level 3)

Terrain is generated via midpoint displacement — a fractal algorithm that produces realistic mountainous profiles. An 80px-wide landing pad is placed randomly in the middle third of the terrain, painted neon green with glow.

The lander itself is a triangle with two legs, rendered in neon cyan with animated thrust flames (particle system). Landing criteria: both leg tips on pad, $|\theta| < 15°$, $|v_y| < 1.0$, $|v_x| < 0.5$. 

// 6 discrete actions
const ACTIONS = {
    NOOP: 0,
    THRUST_MAIN: 1,
    THRUST_LEFT: 2,
    THRUST_RIGHT: 3,
    ROTATE_LEFT: 4,
    ROTATE_RIGHT: 5
};

04 // STATE AND REWARD

The state is an 8-dimensional vector, all normalized to roughly [-1, 1]: 

const state = [
    (lander.x - padCx) / W,      // pad-relative X
    (lander.y - padCy) / H,      // pad-relative Y
    lander.vx / 5,                // normalized horizontal velocity
    lander.vy / 5,                // normalized vertical velocity
    lander.angle / Math.PI,       // normalized angle
    lander.angVel / 0.2,          // normalized angular velocity
    leftLegContact,               // binary: left leg on pad
    rightLegContact               // binary: right leg on pad
];

The reward function went through several iterations (sound familiar from Pong?). The final version:

  • Successful landing: +100 to +140 (with bonuses for uprightness and gentleness)
  • Crash / out of bounds: −100
  • Timeout (500 steps): −50
  • Per frame: approach-pad bonus (closer = better), angle penalty, speed penalty near ground, time penalty (−0.05), thrust penalty (fuel cost)

The per-frame reward shaping is critical. Without the approach bonus, agents have no gradient signal until they accidentally land — which in a 6-action continuous-physics environment almost never happens. The thrust penalty prevents “hover forever” strategies. The angle penalty biases toward upright descent.

05 // THE TRAINING LOOP

Lunar Lander is single-player, so there’s no opponent to calibrate against. Instead, difficulty comes from curriculum learning via spawn randomization:

  • Level 0 (Easy): spawn close to pad, low altitude, no wind
  • Level 1 (Medium): wider spawn offset, higher altitude
  • Level 2 (Hard): large offsets, high altitude, initial velocity
  • Level 3 (Full): everything above plus wind gusts

The level advances automatically when the rolling landing rate (last 20 episodes) exceeds 60%. This is the same principle as the adaptive bot difficulty in Pong — the agent always faces an appropriate challenge.

Auto-train runs 200 physics steps per animation frame, with terrain regenerated each episode. The warmup boot trains DQN for 150 episodes, A2C for 100, and PPO for 80 — all in non-blocking chunks that keep the page responsive.

06 // ALGORITHM-SPECIFIC LESSONS

DQN: Solid but Slow

DQN is the reliable workhorse. With 726 parameters and Double DQN, it eventually learns a decent landing strategy — but it takes 80–120 episodes to reach 50% landing rate. The replay buffer (10K transitions) and per-step $\epsilon$ decay are essential; without them, the Q-values oscillate wildly. DQN’s biggest weakness here: it has no notion of a “policy” — it only knows values, so its behavior can be jerky as Q-values shift between actions.

A2C: Fastest Learner

A2C surprised us by being the fastest to learn. The per-step TD updates give it dense gradient signal — every single frame, the actor gets feedback on whether its action was better than the critic expected. The critic also learns very quickly because the value function for Lunar Lander is relatively smooth (altitude and distance to pad are strongly correlated with outcome). Typical convergence: 40–60 episodes to 50% landing rate.

The entropy bonus ($\beta = 0.02$) is critical. Without it, A2C collapses to a deterministic policy within 20 episodes — usually one that always fires the main thruster, which is locally optimal but can’t handle lateral corrections.

PPO: Most Stable

PPO has the smoothest learning curve. Where A2C occasionally has bad episodes that briefly tank the policy, PPO’s clipping prevents catastrophic updates. The 128-step trajectories with 3 epochs of mini-batch updates give it excellent sample efficiency. Typical convergence: 30–50 episodes to 50% landing rate, with less variance than A2C.

The clipping is visually observable: during early training, A2C’s action probabilities swing wildly between frames, while PPO’s change smoothly and gradually. This is exactly the property that makes PPO suitable for RLHF — you don’t want your language model’s behavior to change drastically between updates.

07 // SEEING ACTOR-CRITIC

This is the teaching payoff. When you select A2C or PPO, a visualization panel appears below the game canvas with two components:

The Critic Confidence Meter: a vertical bar that shows $V(s)$ in real time. It goes from red (low value — “we’re going to crash”) through yellow to green (high value — “we’re about to land”). Watch it during a trained agent’s descent: it starts low, rises as the lander aligns with the pad, and spikes green right before touchdown.

The Actor Action Probabilities: a 6-bar chart showing $\pi(a|s)$ for each action. During early training, all bars are roughly equal (random policy). As the agent learns, you see probability mass concentrate: main-thrust dominates during descent, rotation adjusts for wind, NOOP appears during stable glides. The top-probability action glows green.

If you’ve read the GAN-RL blog post, this should feel viscerally familiar. The actor is the generator — it produces actions (samples). The critic is the discriminator — it evaluates states (scores). The actor tries to take actions that the critic approves of. The critic tries to accurately predict outcomes. Same adversarial game, same convergent dynamic.

In RLHF for LLMs, the actor is the language model (generating tokens), and the critic is the reward model (scoring responses). PPO is the training algorithm. Every piece of this visualization maps directly onto how ChatGPT was trained.

08 // TECHNICAL DETAILS

trainPPO() — The New MiniNet Method

The PPO clipped objective requires a new training method on MiniNet. The key difference from trainPG(): we need the old policy’s probabilities to compute the importance ratio. 

// Importance ratio for the taken action
const ratio = newP / oldP;

// Clipped surrogate
const clipped = Math.max(1 - clipEps, Math.min(1 + clipEps, ratio));
const surr1 = ratio * advantage;
const surr2 = clipped * advantage;

// Gradient flows through the binding term
const useClipped = (surr1 > surr2) ? 1 : 0;

When the advantage is positive (action was good), the ratio is clipped from above at $1 + \epsilon$ — the policy can’t increase the probability of this action too much. When the advantage is negative, it’s clipped from below at $1 - \epsilon$. This creates a “trust region” around the old policy.

GAE Implementation

GAE computes advantages in a single backward pass over the trajectory: 

let gae = 0;
for (let t = T - 1; t >= 0; t--) {
    const delta = reward[t] + gamma * V(s[t+1]) - V(s[t]);
    gae = delta + gamma * lambda * gae;
    advantages[t] = gae;
    returns[t] = gae + values[t];
}

Each advantage is a weighted sum of all future TD errors, with exponential decay controlled by $\gamma \lambda$. At $\lambda = 0$ you get single-step TD (high bias, low variance). At $\lambda = 1$ you get Monte Carlo returns (low bias, high variance). The sweet spot at 0.95 gives smooth advantage estimates that help PPO learn stably.

Parameter Counts

Every parameter is a Float64 in typed arrays — no framework, no tensors, just arithmetic:

  • DQN: MiniNet(8, 64, 6) → (8×64 + 64) + (64×6 + 6) = 576 + 390 = 966
  • A2C Actor: MiniNet(8, 48, 6) → (8×48 + 48) + (48×6 + 6) = 432 + 294 = 726
  • A2C/PPO Critic: MiniNet(8, 48, 1) → (8×48 + 48) + (48×1 + 1) = 432 + 49 = 481
  • A2C/PPO Total: 726 + 481 = 1,207
